The Chaos Language Algorithm:
An Implementation-Oriented Specification
Ben Goertzel w/ GPT-5.5-Pro

Abstract
The Chaos Language Algorithm (CLA) converts a continuous chaotic trajectory into a symbolic string and then induces a compact grammar for that string. The crucial distinction in
this specification is between chunks and meta-symbols. A chunk is a repeated sequential block,
represented by a nonterminal rule such as A → β. A meta-symbol is not a block. A meta-symbol
is a grammatical category: a set of tokens that are substitutable in similar contexts. The algorithm therefore searches over two orthogonal forms of compression: sequential compression by
chunking, and categorical compression by grouping contextually interchangeable tokens.

1

Purpose

Given a scalar or vector time series produced by a deterministic or stochastic dynamical system,
the goal is to infer a grammar G∗ that compactly describes the observed symbolic trajectory
and generalizes it in a controlled way. The induced grammar is selected by a two-part minimum
description length (MDL) objective:
G∗ = arg min [L(G) + L(S | G)] ,

where L(G) is the code length of the grammar and L(S | G) is the code length of the observed string
given that grammar. All accepted operations must preserve exact reconstruction of the observed
string, unless an explicit noise or exception model is added.

Phase 1: Symbolic Dynamics

4.1

Embedding

If the input is scalar, reconstruct the attractor with time-delay embedding. Practical implementations may choose τ by the first minimum of average mutual information and d by false nearest
neighbors, but CLA itself only requires a fixed embedding map.

4.2

Partitioning

Partition the reconstructed state space into cells P = {C1 , . . . , Ck }. The partition may be a
grid, clustering partition, learned decision tree, Voronoi tessellation, or a problem-specific symbolic
dynamics partition. A generating partition is ideal, but the later grammar induction stage is
designed to compensate for crude initial partitions.

4.3

Labeling

Assign each point xt the symbol of the cell it occupies:
st = φ(xt ).

(13)

The result is the base string S0 = s1 · · · sn over Σ0 .

5

Phase 2: Joint Chunk and Category Induction

Phase 2 searches over two classes of grammar edits.

5.1

Chunk Edit

A chunk edit is specified by a repeated block β ∈ V + and a new nonterminal A. It adds a rule
A → β and rewrites selected non-overlapping occurrences of β as A. A chunk edit is valid only if
it preserves exact expansion back to the previous stream.
A practical implementation should enforce two Re-Pair/SEQUITUR-like invariants:
(i) Rule utility: every chunk nonterminal is used at least twice, unless it is the start symbol.
(ii) No dead rules: if a rule’s use count drops below two, inline it and remove it.

5.2

Category Edit

A category edit is specified by a set C ⊆ V , usually obtained by clustering tokens with similar
context distributions. It introduces a meta-symbol M with Ext(M ) = C.
For each token v ∈ V , define a context vector c(v). The simplest usable context vector uses
immediate left and right neighbors:
c(v) = (P (` | v), P (r | v))`,r∈V ∪{⊥,>} ,

(14)

where ⊥ and > mark beginning and end of stream. Wider context windows may be used. Two
tokens are categorically similar when their context distributions are close, for example when
JS(c(v), c(w)) ≤ θ.

(15)

A category edit is accepted only when the resulting grammar and parse reduce the MDL objective. This prevents arbitrary clustering from inflating the grammar.

5.3

Renormalization

After an accepted chunk or category edit, the current stream, parse, rule uses, and context statistics
are updated. The next round operates on the new vocabulary. Thus a later chunk may contain
earlier chunks, and a later category may group base symbols, chunk nonterminals, or previously
created category-bearing parse atoms when the implementation allows it.

Appendix: Guidance for Coding Agents

A.1

Non-Negotiable Semantic Constraints

A coding agent implementing CLA must preserve the following distinctions.
C1. A chunk is a sequence abbreviation. Implement it as a nonterminal rule A → β.
C2. A meta-symbol is a category. Implement it as a set-valued object M with Ext(M ) ⊆ V .

7

C3. Do not implement a meta-symbol as a compressed n-gram. The edit that replaces abc by
a new token is a chunk edit, not a category edit.
C4. A category occurrence must preserve the identity of the observed member. Store it as M [v]
or store an equivalent side table mapping parse positions to members.
C5. Every accepted edit must reduce the same MDL objective used by the rest of the program.
Do not use frequency alone as an acceptance rule.
C6. The implementation must be able to expand G and P back to the original raw string S0
after every accepted edit.

A.3

Minimal Milestone Plan

A robust implementation can be built in five milestones.
M1. Symbolization only. Convert a trajectory to S0 using a fixed partition. Unit test that
the same point always maps to the same symbol.
M2. Chunk-only grammar. Implement repeated n-gram proposals, non-overlapping replacement, rule expansion, rule use counts, and exact reconstruction.
M3. MDL scoring. Replace frequency thresholds with a bit-based objective. Unit test that
an edit is rejected when its model overhead exceeds its data savings.
M4. Hard category induction. Compute context histograms, cluster tokens by context similarity, create disjoint meta-symbols, and store category occurrences as M [v].
M5. Unified search. Put chunk and category proposals into the same priority queue and
accept the proposal with the largest negative ∆L.

A.4

Context Distribution Details

For a first implementation, use a context width of w = 1. For every occurrence of token v at
position i, count

cosine distance.
A category candidate C should usually satisfy:
(i) |C| ≥ 2;
(ii) each member has a minimum occurrence count;
(iii) average pairwise context distance is below threshold θ;
(iv) the candidate reduces L(G, S) after member choices are encoded.

A.6

Acceptance Tests

A coding agent should include at least the following tests.
T1. Exact expansion. After every accepted edit, expanding the parse returns exactly S0 .
T2. Chunk identity. If A → abc, then every A expands to abc and never to a set of alternatives.
T3. Category identity. If M = {x, y}, then M is not expanded as xy or yx; it expands to
exactly one chosen member at each occurrence.
T4. Frame generalization. From
a x b

a y b

a x b

the system may propose M = {x, y} in the frame a b.
T5. MDL rejection. A proposed category containing unrelated rare symbols must be rejected
when its extension cost is larger than its compression savings.
T6. Rule pruning. If a chunk rule’s use count falls below two, it is inlined or removed.
T7. Determinism. With the same random seed and input, the same sequence of accepted
edits is produced.

A.7

Common Failure Modes

F1. Conflating chunks and categories. This is the main error to avoid. Repeated string
abc implies a possible chunk. Similar contexts for x and y imply a possible category.
F2. Accepting by frequency only. A frequent block or cluster is not useful unless it reduces
total description length.
F3. Losing exact reconstruction. If category occurrences do not store chosen members, the
algorithm cannot reconstruct the observed trajectory.
F4. Overlapping category ambiguity. Start with hard, disjoint categories. Allow overlapping categories only after the parse stores which category sense is used at each position.
F5. Unstable indices after rewriting. Chunk replacements change stream length. Recompute or incrementally update occurrence indices rather than reusing stale positions.
