 Initial Abstract Algorithmic Chemistry Experiments in PeTTa
A PeTTa-First, MORK-Ready Research and Implementation Plan
                        Prepared for human researchers and coding agents

                                                 June 2026


                                                  Abstract
          This document specifies an initial research and software-development program for abstract al-
      gorithmic chemistry in PeTTa and an Atomspace/MeTTa context. The aim is to obtain measur-
      able emergence of complex autocatalytic sets and associated evolutionary or ecological dynamics
      before introducing semantic graphs, MORK execution, PLN, MOSES, or music-composition-
      specific molecules. The first chemistry is deliberately abstract: molecules are small symbolic
      terms, token sequences, and later rule molecules; reactions are typed, bounded, catalytic rewrite
      rules over multisets. The design keeps clear seams for later acceleration or migration to MORK,
      especially for matching, sampling, canonicalization, bulk analytics, and structural rule evolution.
          The document has two audiences. The main body is for human readers: it explains moti-
      vation, conceptual choices, scientific questions, implications, and a staged research trajectory
      from abstract chemistry to semantic and musical chemistry. The appendix is for coding agents:
      it gives step-by-step experiments, atom schemas, phase loops, analytics algorithms, repository
      layout, tests, acceptance criteria, and review checkpoints suitable for an OpenClaw-style imple-
      mentation workflow using a coding model for routine development and intermittent strategic
      review by a stronger reasoning model.

1    Purpose and scope
The immediate goal is not to build semantic graph chemistry, music chemistry, or a full ActPC-
MORK stack. The immediate goal is to make a small but genuinely interesting algorithmic chem-
istry work in PeTTa alone: a chemical soup whose state is represented in an Atomspace, whose
reaction rules are expressed in a MeTTa-like idiom, and whose run logs can be mined for autocat-
alytic structure, parasitism, succession, ecological niches, and causal relevance.
    The work should begin with an abstract symbolic chemistry for four reasons. First, the ab-
stractions make it possible to run many experiments quickly and to understand failures. Second,
autocatalytic structure can be detected and tested without confounding it with natural-language
parsing, semantic normalization, PLN truth-value propagation, or musical aesthetic scoring. Third,
the same core software objects–molecules, reaction events, rule molecules, chambers, catalysts, ana-
lytics, ablations, and traces–will still be needed in semantic and musical versions. Fourth, a simple
PeTTa-only implementation reduces integration risk while preserving a clean migration path to
MORK.
    The proposed first milestone is:

     Demonstrate spontaneous, measurable, replayable, and intervention-relevant autocat-
     alytic organization in a bounded abstract PeTTa chemistry.

    This phrase is intentionally restrictive. “Spontaneous” means the most interesting autocatalytic
sets should not be hand-coded, although the detector should first be validated on hand-planted
examples. “Measurable” means the system must report diversity, recurrence, closure, persistence,
productivity, and ablation impact. “Replayable” means all stochastic choices are seedable and all
reaction events are logged. “Intervention-relevant” means candidate sets must be ablated, boosted,
or shuffled to see whether they matter.


2    Why start with abstract chemistry rather than semantic graphs
Semantic graph chemistry is the long-term target, but it introduces several additional degrees of
freedom at once: graph normalization, variable-bearing matching, contextual implication weights,
task reward, truth-value dynamics, and natural-language realization. These are valuable later, but
they obscure the first question: can the system cultivate useful recurrent reaction networks at all?
    The abstract chemistry proposed here keeps the shape of the later system while removing domain
complications. In the first version:

• Molecules are symbolic sequences or small trees rather than semantic graphs.

• Reaction rules are typed catalytic rewrites rather than PLN-weighted semantic transformations.

• Chambers are abstract ecological environments rather than discourse, biomedical, or musical
  contexts.

• Reward is persistence, productivity, complexity, prediction improvement, or controlled task score
  rather than question answering or aesthetic evaluation.

• Autocatalytic sets are detected from event logs and molecule-rule dependency graphs rather than
  from semantic inference loops.




                                                 5
   This does not abandon semantic chemistry. It creates a substrate that can later host semantic
graph fragments as molecules and contextual graph rewrites as reactions. The software should
therefore avoid assumptions that molecules are strings forever. A molecule should be an opaque
object with typed views, one of which may initially be a token sequence and later may be a graph,
phrase, chord progression, or rule body.


3     Relation to the ActPC-MORK and semantic-chemistry designs
The ActPC-MORK design argues for a two-level architecture: a fast local inner loop over compact
indexed atoms, and a slower structural loop that proposes new rules, abstractions, and meta-guards
from traces and credit signals. This document keeps that separation but collapses it into PeTTa
for the first implementation. MORK, MM2, MOSES, PLN, AIRIS, CENF, and optimal transport
are not part of the first milestone.
    The first implementation should nevertheless preserve their future interfaces. In particular:

• The inner loop should be phase-based and event-log-driven.
• Hot-path facts should be relation-first and context-scoped.
• Source rules and compiled matching facts should be separable, even if the first compiler is trivial.
• Stochastic sampling, scoring, ACS scanning, canonical hashing, and replay should be written
  behind replaceable request/response interfaces.
• New rules should enter as trial rules and be promoted or retired by evidence.
• Analytics should produce atoms, not merely external plots.

    The semantic-graph chemistry design adds another important lesson: a loop is not interesting
merely because it is self-reinforcing. Useful loops must pay rent. For the abstract chemistry, this
means that ACS candidates should be evaluated by interventions: remove them, boost them, shuffle
their catalyst links, and compare the resulting dynamics. This is the abstract precursor of causal
semantic ACSs.


4     Core scientific questions
The experiments should be organized around concrete questions rather than merely around code
milestones.

4.1   Autocatalytic emergence
Can a random or weakly structured catalytic term-rewrite chemistry produce self-sustaining sets of
molecules and reactions that satisfy closure and persistence criteria? Are there parameter regimes
in which such sets emerge more often than in degree-preserving shuffled controls?

4.2   Evolutionary and ecological dynamics
Once ACSs exist, do they show ecological behavior? We would like to observe birth, death, suc-
cession, invasion, parasitism, mutualism, niche specialization, collapse, and recovery. These should
not be described only anecdotally; they should be detected from event logs and summarized across
seeds.

                                                  6
4.3    Endogenous rule evolution
Can rules themselves become molecules? Can rule-mutating reactions produce variants that survive
selection? Do trace-guided mutations outperform random mutations? Do any autocatalytic sets
become dependent on evolved rules rather than only on hand-coded bootstrap rules?

4.4    Prediction and active weighting
Can an ActPC-like predictive wrapper improve stability, productivity, or task performance without
freezing the soup into a trivial attractor? Can the system learn which reaction families reduce next-
window prediction error or improve controlled external reward?

4.5    Causal relevance of ACSs
Do detected ACSs actually matter? A candidate ACS should not be accepted as a scientific result
until it passes paired replay or ablation tests. Useful metrics include reward drop under ablation,
productivity drop, persistence change, diversity change, and resistance to parasites.


5     Recommended starting chemistry
The first chemistry should be a typed catalytic multiset rewrite chemistry. The state of a chamber
at tick t is a bounded multiset of molecule ids with abundances:

                                          St (C) = {(mi , ai )}ni=1 .

Each molecule has one or more typed views. Initially the most important view is a token sequence:

                            m = [x1 , x2 , . . . , xk ],       xi ∈ Σ,   k ≤ Lmax .

Later views may include trees, rule bodies, compressed macro-molecules, semantic graphs, or mu-
sical motifs.
    A reaction rule has the schematic form:
                                          catalyst pattern
                                P1 + P2 −−−−−−−−−−−−−→ Q1 + Q2 .
                                         inhibitor pattern

Here Pi and Qi are patterns over molecule views, not necessarily concrete molecule ids. The first
version may restrict all reactions to one or two reactants and one or two products. This restriction
is useful because it makes matching, event logging, and hypergraph reconstruction simple.

5.1    Initial reaction families
The following reaction families are sufficient for the first major experiments:

    Family                  Role
    concat                  Combines two short token sequences into a longer sequence, subject
                            to capacity and length limits.
    split                   Splits a longer sequence into two shorter sequences. This gives
                            catabolism and prevents irreversible growth.
    mutate-token            Changes one token in a sequence. This gives local variation.


                                                           7
     copy                      Replicates a molecule under catalytic conditions. This supports run-
                               away amplification and parasite tests.
     compress                  Creates a macro-molecule from a repeated or high-frequency motif.
     decompress                Re-expands a macro-molecule, allowing macro-level ACSs to interact
                               with ordinary molecules.
     rule-mutate               Produces a trial rule molecule by modifying an existing rule. This is
                               introduced only after Experiments 0–2.
     rule-compose              Creates a rule from two rules when the products of one match the
                               reactants of the other. This is introduced after rule molecules exist.

5.2      Catalysis and inhibition
Catalysis should start simple but not arbitrary. A molecule can catalyze a rule when its token
sequence or macro label matches a catalyst pattern associated with that rule. Examples:

A sequence containing motif M catalyzes rules that produce M.
A repeated subpattern catalyzes copy and compress rules.
A palindrome-like sequence catalyzes reverse or split rules.
A macro molecule catalyzes reactions using its component motif.
A parasite marker inhibits repair or closure reactions.

     The scoring function for a candidate reaction application can initially be:

    s(R, b, C, t) = `R + βc Cat(R, b, C, t) − βi Inhib(R, b, C, t) − λCost(R, b) + βn N ovelty(R, b, C, t),

where R is the rule, b is the binding, C is the chamber, `R is the rule logit, Cat is the catalytic
support, Inhib is inhibition, Cost is length or compute cost, and N ovelty is a bounded novelty
bonus. The novelty term should be small. A large novelty term will create novelty addiction.


6      PeTTa-first architecture
The first implementation should have four layers.

6.1      Layer A: Atomspace state
The Atomspace stores molecule definitions, abundances, rules, chambers, transient candidates,
selected reactions, event logs, inferred catalysis links, ACS annotations, snapshots, and experiment
metadata. It should also store enough information to recreate the run from a seed and a config file.

6.2      Layer B: Phase engine
A chamber tick should be explicit and inspectable:

tick:
  begin_tick
  inflow_food
  decay_and_dilution
  derive_active_signatures
  match_reaction_candidates


                                                      8
    score_candidates
    sample_reactions
    fire_reactions
    log_events
    update_abundances
    mine_catalysis_window
    scan_acs_window
    structural_mutation_step
    cleanup_transients
    end_tick

   Not every phase must be implemented as pure PeTTa rewriting. However, every phase should
read and write atoms through a narrow adapter so that the same protocol can later be handled by
MORK or host-side kernels.

6.3    Layer C: Analytics
The analytics layer computes catalytic strengths, ACS candidates, persistence, diversity, ecological
events, and intervention impact. It should write results back into the Atomspace as atoms. This is
crucial: the chemistry should be able to react to its own analytics. For example, a persistent ACS
may become a macro-molecule, a parasite motif may become an inhibitor, and a high-impact ACS
may bias rule mutation.

6.4    Layer D: Replaceable kernel boundary
Even in the PeTTa-only version, expensive or stochastic operations should be represented as request
atoms. The first implementation may answer them in simple local code, but the calling convention
should not assume that.

(sample-request C T)
(score-request C T)
(acs-scan-request C T W)
(catalysis-scan-request C T W)
(replay-ablation-request C T Snapshot ACS Seed)
(canon-hash-request Obj)
(rule-distance-request R1 R2)

   Later, these requests can be answered by MORK, host kernels, parallel workers, or specialized
analytics tools without changing the scientific representation.


7     Core atom conventions
Hot-path atoms should be relation-first, with grounded context or object keys early and variables
late. The first implementation can be more forgiving than MORK, but it should train the codebase
into MORK-compatible habits.

with which reactants, catalysts, products, and seed state, it is not an acceptable event.


8     Analytics for autocatalytic sets
The analytics layer turns event logs into scientific claims. There are four levels of analysis.

8.1   Descriptive chemistry metrics
Basic time-series metrics should be emitted for every run:

unique molecule count
unique rule count
abundance entropy
reaction entropy
mean molecule length or tree depth
macro molecule count
turnover rate
dominant lineage age
candidate count per tick
runtime per tick

   These metrics tell us whether the soup is alive, frozen, exploding, or degenerate, but they do
not yet prove autocatalysis.

8.2   Empirical catalysis mining
For each molecule m and reaction rule r, estimate an empirical catalytic strength over a recent
window W :
                                            P (fire r | m present) + 
                              κ(m, r) = log                            .
                                            P (fire r | m absent) + 
A simple confidence value is:
                                                        Nm,r
                                      conf (m, r) =           .
                                                     Nm,r + k
The analytics layer writes:
(catalyzes M17 R10 1.28 0.64)
(inhibits M23 R10 0.93 0.58)
   These atoms can later influence candidate scoring, rule mutation, and macro ACS creation.
The first version should distinguish explicit catalyst rules from empirically mined catalyst effects.
Both are useful, but they answer different questions.

8.3   ACS and RAF-like closure
For each window W , construct a bipartite directed hypergraph:
Molecule -> Reaction if molecule is a reactant.
Molecule -> Reaction if molecule is a catalyst.
Reaction -> Molecule if molecule is a product.
Food -> Molecule if molecule is supplied externally.
   A candidate ACS should satisfy at least the following conditions:
• Reaction closure: reactions in the set produce molecules that support other reactions in the set.
• Catalytic closure: each reaction has a catalyst from the food set or from molecules produced by
  the set.
• Food reachability: reactants can be built from food molecules plus products of the set.
• Persistence: the set recurs across multiple windows or survives for more than a minimum number
  of ticks.
• Nontriviality: the set contains more than a single reflexive copy rule or a one-rule artifact unless
  explicitly marked as a degenerate ACS.
   The output should be represented as atoms:
(acs ACS42)
(acs-window ACS42 C1 T000100 T000300)
(acs-member-mol ACS42 M17)
(acs-member-rule ACS42 R10)
(acs-food-supported ACS42 true)
(acs-catalytically-closed ACS42 true)
(acs-size-mol ACS42 11)
(acs-size-rule ACS42 6)
(acs-persistence ACS42 200)
(acs-productivity ACS42 3.8)

                                                 12
8.4   Causal relevance by replay and ablation
A candidate ACS becomes scientifically interesting when it matters under intervention. Let J
be a run-level objective such as productivity, diversity, complexity, target production, prediction
improvement, or explicit task reward. For an ACS A, define:

                         Impact(A) = E[J | normal] − E[J | ablate(A)].

The replay protocol should use the same snapshot and seed when possible:

Condition 1: normal replay.
Condition 2: remove ACS member rules.
Condition 3: remove ACS member molecules.
Condition 4: boost ACS member molecules and rules.
Condition 5: degree-preserving catalyst shuffle control.

    Output atoms:

(acs-causal-test ACS42 ablation reward-drop 0.31 0.44)
(acs-causal-test ACS42 activation reward-gain 0.27 0.39)
(acs-causal-test ACS42 shuffled-control-drop 0.04 0.31)
(acs-clarity ACS42 0.76)
(acs-redundancy ACS42 0.22)

    The distinction between active ACS and causal ACS should be explicit:

active ACS: self-sustaining and recurrent
useful ACS: self-sustaining and associated with reward or productivity
causal ACS: useful ACS whose ablation or activation changes outcomes


9     Experimental trajectory
The project should progress through a sequence of experiments that each answer a specific question
and leave behind reusable code.

9.1   Experiment 0: deterministic smoke test
This validates schemas, abundance updates, event logging, and replay. It uses a hand-coded toy
system with a few molecules and reactions. No emergence is claimed.

9.2   Experiment 1: hand-planted ACS recovery
This validates the ACS detector. A known autocatalytic set is embedded in a soup with distractor
reactions. The detector should recover it and ablation should matter.

9.3   Experiment 2: random catalytic polymer chemistry
This is the first emergence experiment. Molecules are token sequences. Reactions include con-
cat, split, mutate, copy, compress, and decay. Catalyst links are partly pattern-based and partly
random. The experiment searches for parameter regimes where ACSs emerge more often than in
shuffled controls.

                                                13
9.4   Experiment 3: rule molecules and endogenous rule evolution
Rules become molecules. Rule-mutating reactions generate trial rules. Trial rules are promoted
or retired based on recent credit, ACS participation, and cost. This tests whether algorithmic
chemistry can alter its own reaction space.

9.5   Experiment 4: ecological chambers, migration, and parasites
Multiple chambers have different food profiles, decay rates, and capacities. Molecules and rules
can migrate. Parasites exploit ACS products without contributing to closure. This tests niche
formation, invasion, collapse, and recovery.

9.6   Experiment 5: active-predictive weighting
The system predicts the next-window molecule distribution. Rules are rewarded for reducing pre-
diction error and improving controlled objectives. This adds an ActPC-like layer while keeping the
substrate abstract.

9.7   Experiment 6: trace-guided structural mutation
Instead of purely random rule mutations, the system uses traces, high-credit ACS members, parasite
failures, and high-surprise transitions to propose structural mutations. This is the PeTTa-only
precursor to later MOSES/MORK structural proposal machinery.

9.8   Experiment 7: causal ACS validation archive
Detected ACSs are subjected to paired replay, ablation, activation, and shuffled controls across
many seeds. The output is an archive of causal ACSs, degenerate loops, parasites, and failed
candidates.


10    Expected outcomes and implications
A successful first phase would not prove AGI, musical creativity, semantic reasoning, or biological
chemical realism. It would establish something more specific and more useful: a working exper-
imental substrate in which symbolic rewrite molecules can form measurable, replayable, causally
testable reaction networks.
    That substrate has several implications.

• For cognitive architecture, it provides a concrete testbed for self-modifying rule ecologies before
  they are connected to language or perception.

• For MORK integration, it identifies which operations deserve acceleration: candidate matching,
  stochastic sampling, window analytics, replay, and structural rule proposal.

• For semantic chemistry, it clarifies which ACS analytics are domain independent and which
  require graph-specific semantics.

• For music, it gives a path from abstract motif chemistry to phrase, rhythm, harmony, and style
  chemistries.



                                                 14
• For coding-agent development, it gives a sequence of testable milestones rather than a vague
  research program.

   A negative result is also informative. If the abstract system fails to produce nontrivial ACSs
except under heavy hand coding, then the design should be simplified further, the reaction family
should be revised, or the analytics may be detecting the wrong structures. Failure should be logged
with the same seriousness as success.


11    Later path to semantic chemistry
Semantic graph chemistry should be introduced only after the abstract substrate has working event
logs, ACS mining, ablation, and multi-chamber dynamics. The mapping is straightforward:

     Abstract chemistry                Semantic chemistry
     Token sequence molecule           Semantic graph fragment or FUSE-NF-like molecule
     Catalytic rewrite rule            Contextual semantic graph transformation
     Chamber                           Discourse, domain, question, or world context
     Food                              Parsed sentences, KB facts, primitive roles, question
                                       graph
     ACS                               Self-sustaining semantic inference or generation loop
     Reward                            QA score, explanation compactness, hypothesis utility,
                                       narrative power
     Ablation                          Rule, module, chamber, or ACS intervention

    The main lesson to carry over is not a specific token rule. It is the discipline of event logs,
closure detection, intervention testing, and treating inference control as something that evolves
inside the chemistry.


12    Later path to music chemistry
Music chemistry should also wait until abstract ACS dynamics work. The first music version should
use symbolic motifs rather than audio. A possible mapping is:

     Abstract chemistry                Music chemistry
     Token sequence                    Pitch, rhythm, interval, chord, or phrase motif
     Concat                            Phrase concatenation or rhythmic extension
     Split                             Motif extraction or phrase segmentation
     Mutate-token                      Pitch, duration, articulation, or harmony variation
     Copy                              Repetition, sequence, ostinato, motivic recall
     Compress                          Theme abstraction or style macro
     Catalyst                          Key, meter, groove, harmonic context, instrumenta-
                                       tion, style marker
     ACS                               Self-sustaining compositional idiom or motif ecology
     Reward                            Coherence, novelty, tension-release, style fit, human or
                                       model score

   The first music experiment should not try to generate finished songs. It should ask whether
motif-rewrite chemistries form persistent, rewarded ACSs that produce coherent phrase families.

13    Recommended implementation governance
This project is well suited to an agentic development process, but only if the agent is constrained
by tests and artifacts. A coding agent should not be asked to “implement algorithmic chemistry”
in one step. It should be given the appendix as a milestone ladder.
    A practical workflow is:

• An OpenClaw-style coding agent performs routine implementation, refactoring, tests, and exper-
  iment automation.

• GPT-5.5-level coding assistance is used for ordinary software tasks: schema files, adapters, CLI
  runners, tests, plotting, and parameter sweeps.

• GPT-5.5-Pro-level strategic review is called at milestone boundaries: after Experiment 0, after
  planted ACS recovery, after first random chemistry sweeps, after rule evolution, and before
  semantic or music extensions.

• Every strategic review receives the same package: config, seed list, event-log summary, metrics
  CSV, ACS archive, ablation results, known failures, and next proposed changes.

    The review question should not be “does the code look clever?” It should be: what did the
experiment demonstrate, what did it fail to demonstrate, and which next change most increases
scientific information per engineering hour?

E    Candidate matching guidance

interface should already look like a future indexed matcher.

procedure MATCH_REACTION_CANDIDATES(space, C, T):
    active_rules = query(rule-status R active)
    active_mols = query(abund C T M Count where Count > 0)
    candidates = []

     for R in active_rules:

G     ACS scanner pseudocode
The first scanner can be conservative. It is better to miss some ACSs than to label every cycle as
an ACS.

procedure SCAN_ACS(space, C, T, window):
    events = read_events(C, T-window, T)
    graph = build_bipartite_graph(events)

    components = strongly_connected_components(graph)
    candidates = []

    for comp in components:
        if count_rules(comp) < min_rules:
            continue
        if count_molecules(comp) < min_molecules:
            continue

         closure = RAF_CLOSURE(comp, food_set(C), graph)
         if closure.catalytically_closed and closure.food_supported:
             A = allocate_acs_id()
             write_acs_atoms(A, C, T-window, T, closure)
             candidates.append(A)

    score_persistence_and_productivity(candidates)
    return candidates
end procedure

procedure RAF_CLOSURE(component, food, graph):
    available = set(food)
    chosen_rules = empty set
    changed = true

    while changed:
        changed = false
        for rule in component.rules:
            if rule in chosen_rules:
                continue
            if reactants(rule) subset available and catalyst_supported(rule, available):
                chosen_rules.add(rule)
                available.add_all(products(rule))

                                               22
                  changed = true

    # Prune unsupported rules until fixed point.
    changed = true
    while changed:
        changed = false
        for rule in copy(chosen_rules):
            if not reactants(rule) subset available:
                chosen_rules.remove(rule)
                changed = true
            if not catalyst_supported(rule, available):
                chosen_rules.remove(rule)
                changed = true
        available = food union products(chosen_rules)

    return closure(chosen_rules, available)
end procedure

procedure TEST_ACS_CAUSALITY(snapshot, ACS, seed, config):

    cfg1 = config with ACS member rules disabled
    ablate_rules = REPLAY(snapshot, seed, cfg1)

R     Testing checklist
R.1    Unit tests
Atom parser round trip.
Molecule canonical hash stable across runs.
Rule canonical hash stable across equivalent source forms.
Softmax sampling deterministic under seed.
Abundance updates conserve counts when configured to conserve.
Decay never creates negative abundance.
Candidate caps are enforced.
ACS scanner recovers planted ACS.
ACS scanner rejects simple non-catalytic cycle when catalyst support is absent.
Ablation replay uses identical seed and snapshot.
Trial duplicate rule is retired.

R.2    Integration tests
Run exp00 for 100 ticks and compare event log to golden file.
Run exp01 and recover planted ACS with precision above threshold.
Run exp02 small sweep and produce metrics files.
Replay a snapshot and reproduce future events under same seed.
Run ablation on planted ACS and observe configured productivity drop.


S     OpenClaw and model-review workflow
A coding agent should work in short branches. Each branch should have one experiment or one
infrastructure target. A suggested process:

1. Implement feature behind tests.
2. Run unit tests.
3. Run smallest relevant experiment.
4. Save outputs and summary.

T     MORK migration seams
Keep these seams explicit from the beginning.

      Subsystem                     Later MORK or host acceleration target
      Atom storage                  Prefix-sensitive indexed storage of relation-first facts
      Candidate matching            Compiled trigger/guard/template facts and hot-path
                                    matching
      Sampling                      Grounded stochastic sampler with seed discipline
      Scoring                       Numeric kernel for candidate scores and costs
      ACS scan                      Bulk graph analytics over event windows
      Replay                        Snapshot and deterministic event replay engine
      Canonical hash                Rule and molecule hash-consing
      Rule distance                 Structural and behavioral neighbor graph for rule space
      Structural mutation           MOSES or other slower proposal machinery

   Do not wait until the port to define these boundaries. The first PeTTa version should already
behave as if these calls could be remote or accelerated later.

W     Stop conditions for coding agents
A coding agent should stop and request review when any of the following occurs:

1. Deterministic replay fails.
2. Candidate counts grow superlinearly in small tests.
3. ACS detector reports many ACSs in shuffled controls.
4. Experiment 1 planted ACS is not recovered.
5. Rule mutation creates duplicate floods.
6. Metrics are not interpretable from saved outputs.
7. The code requires semantic graphs or MORK to pass abstract tests.
8. Any feature cannot be unit-tested without a full run.


X     Bridge to semantic and music versions
After Experiment 7, create two small bridge prototypes rather than immediately building full
applications.

X.1   Semantic bridge prototype
Replace token sequence molecules with tiny hand-authored graph motifs. Keep the same reaction
engine and ACS scanner. Do not use open-domain parsing. Test whether the same ACS analytics
work on graph-shaped molecules.

X.2   Music bridge prototype
Replace token sequences with symbolic motifs:
