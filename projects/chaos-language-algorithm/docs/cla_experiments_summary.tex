\begin{abstract}
The Chaos Language Algorithm (CLA) prototype maps deterministic dynamical
trajectories to fixed-partition symbolic streams and greedily induces chunk and
category structure under an approximate minimum-description-length objective.
This paper consolidates the experiment records available as of 2026-07-09.
Recorded 256-symbol controls cover the logistic map, Lorenz-63, Rossler,
Mackey-Glass, and Lorenz-96, including Lorenz-96 dimensions 8 through 24.
Every recorded run reports exact reconstruction. A later 1024-symbol,
20-dimensional Lorenz-96 smoke run used a bounded suffix-trie miner and the
Jensen-Shannon category-proposal path. It reconstructed exactly, observed 510
unique compound symbols, learned eight chunk rules, reported an approximate
score of 1021.2, and measured 2.554301110096276 seconds of model-fit wall time.
The evidence establishes functional correctness on these controls and a first
OmegaSim-scale dimensionality smoke test. It does not yet establish attractor
classification accuracy, a brute-force-versus-trie speedup, peak-memory
improvement, statistical generalization, or performance on an OmegaSim trace.
\end{abstract}

\section{Introduction}

CLA is intended to recognize grammatical structure in strange attractors,
strange transients, and related trajectories. The project was promoted as a
prerequisite to resuming OmegaSim work: before interpreting an OmegaHive trace,
the detector should be calibrated on known systems. The implemented prototype,
\texttt{chaoslang}, is pure Python and backend-neutral. Its primary invariant is
lossless symbolic reconstruction rather than predictive accuracy.

Two semantic objects must remain distinct. A \emph{chunk} is a sequential
nonterminal such as $N \rightarrow abc$. A \emph{category} represents
substitutable members in related contexts. Every category occurrence stores its
observed member, conceptually $M[x]$, so expansion returns the original symbol
rather than the entire member set. Candidate edits are accepted only when the
prototype's approximate description-length score decreases, and exact expansion
is asserted after accepted edits.

The present paper reports only claims supported by project records, repository
source, tests, or experiment records. The companion provenance note enumerates
those sources and records evidence gaps.

\section{Method and Configuration}

\subsection{Trajectory generation}

The benchmark module implements five deterministic controls. The logistic map
uses direct iteration with $r=4.0$ and $x_0=0.123$. Lorenz-63 and Rossler use
fixed-step fourth-order Runge--Kutta integration. Their recorded parameters are,
respectively, $(\sigma,\rho,\beta)=(10,28,8/3)$ with $dt=0.01$ and initial
$(1,1,1)$, and $(a,b,c)=(0.2,0.2,5.7)$ with $dt=0.05$ and initial
$(0.1,0,0)$. Mackey-Glass uses fixed-step Euler integration with a discrete
17-step delay buffer, $dt=0.1$, $\beta=0.2$, $\gamma=0.1$, $n=10$, and initial
history 0.5. Lorenz-96 uses fixed-step Runge--Kutta integration with $F=8.0$,
$dt=0.01$, and initial state
$[8.0]^{D-1}+[8.01]$.

These are numerical controls generated by the local implementation. The run
records do not include independent numerical validation against a reference
integrator, Lyapunov exponents, or a demonstrated chaotic regime for every
finite recorded segment. Accordingly, ``attractor control'' below identifies
the generating system and parameterization, not a separately verified chaos
label for each sample.

\subsection{M1 symbolization}

For every coordinate, M1 divides a rectangular interval into equal-width bins.
Unless explicit bounds are supplied, bounds are inferred once from the complete
recorded trajectory and then held fixed while symbolizing that trajectory.
Values outside supplied bounds are clamped to an edge bin. A vector observation
becomes one compound token containing all per-axis bin indices. All recorded
experiments in Table~\ref{tab:runs} use four bins per axis. This creates as many
as $4^D$ possible compound labels and therefore rapidly increases observed
symbol cardinality with dimension.

\subsection{Grammar induction}

The public default configuration uses n-grams of lengths 2 through 5, at least
two non-overlapping uses, categories enabled, eight maximum greedy iterations,
and seed 0 unless overridden. At each iteration the learner enumerates chunk
and category proposals, applies each proposal to a copied state, scores the
candidate, and accepts the lowest strictly improving score. Equal scores use a
deterministic proposal key. Although a private random generator is initialized
from the seed, the inspected fit loop does not use it; determinism in the
current implementation follows from deterministic enumeration and lexical
tie-breaking.

The scorer is an explicitly approximate proxy. For a chunk production it
charges 0.8 plus right-hand-side length; for a category it charges 14 plus the
member count; it also charges 0.1 per edit-log entry. Ordinary parse entries
cost one unit. A category occurrence costs
$1-\log_2 p(\mathrm{member}\mid\mathrm{category})$. Experiment records call the
result ``bits,'' but the scorer documentation calls it token-count units or an
MDL-like proxy. This paper therefore reports \emph{score units}; the values
should not be interpreted as a calibrated bit code without a complete coding
scheme.

The exact context inducer groups tokens having the same set of immediate
left/right contexts. The JS inducer instead clusters context histograms below a
Jensen--Shannon divergence threshold; the 1024 by 20D run used threshold 0.1.
Category occurrences retain their members, and edit application asserts exact
reconstruction.

\subsection{Bounded suffix-trie miner}

Commit \texttt{97cfb4f} added a separate suffix-trie miner. Commit
\texttt{b344aa3} changed the default n-gram miner to use a bounded suffix trie.
Both commits are on branch
\path{agent/suffix-trie-miner} and are ancestors of the current local
\texttt{main}; both branch names
currently point to \texttt{b344aa3}. No separate merge commit is present in the
inspected history. The trie inserts at most \path{max_ngram} entries per
suffix and shares common prefixes. For fixed maximum n-gram length its node
bound is $O(N\,n_{\max})$, which is linear in stream length when $n_{\max}$ is
fixed. Tests compare proposal signatures with the prior public miner behavior,
exercise category occurrences and compound symbols, check non-overlap, and
bound trie nodes.

The historical brute-force implementation was recoverable from the parent of
\texttt{b344aa3}: it materialized each window tuple and key separately for every
n-gram length. However, the recorded 1024 by 20D run did not execute that old
implementation. Thus no empirical speedup or memory reduction can be claimed.

\section{Results and Interpretation}

Exact reconstruction held in every recorded experiment. The 256-symbol
baseline suite also demonstrated that the implementation can create nested
chunk hierarchies: this is stated explicitly in the logistic, Lorenz-63,
Mackey-Glass, and selected Lorenz-96 records. The baseline scores range from
44.4 for the scalar Mackey-Glass stream to 234.2 for five-dimensional
Lorenz-96. These values compare compression under one fixed proxy and should
not be read as absolute entropy estimates.

In the Lorenz-96 scaling records, observed compound-symbol cardinality rose from
56 at dimension 5 to 148 at dimension 24. Scores remained close to the raw
256-entry parse cost at dimensions 16 through 24, and final production counts
fell to between three and six. This is evidence that the current direct
four-bin compound symbolization leaves little repeated local structure for the
current chunk grammar at those settings. It is not evidence that the underlying
dynamics lack structure: symbolization, finite sample length, n-gram bounds, and
the approximate scorer can all hide it. The dimension-8 score is lower than the
dimension-5 score, so the small suite does not support a strictly monotone score
claim.

The 1024 by 20D smoke run expanded the sample while selecting the named
suffix-trie and JS paths. It observed 510 unique symbols among 1024 positions,
accepted eight chunk rules, and accepted no category edit. The final score,
1021.2, is close to the uncompressed parse length in the scorer's units. The
result demonstrates completion and exactness at the targeted dimensionality,
but it does not demonstrate a benefit from JS clustering in this run, because
no category edit was accepted. Likewise, it does not establish a trie speedup,
because there is no matched old-miner run.

\section{Limitations}

\begin{itemize}
  \item There is no non-chaotic control suite, shuffled surrogate, periodic
  baseline, or labeled classification task. Consequently sensitivity and
  specificity for detecting chaos or attractor grammar are unknown.
  \item Each recorded parameter setting appears once. There are no confidence
  intervals, perturbation sweeps, held-out trajectories, or cross-seed studies.
  \item Most runs contain only 256 retained samples. Bounds inferred from the
  full trajectory leak global range information into symbolization and prevent
  a clean train/test protocol.
  \item The score is a heuristic objective, not a complete prefix code. Calling
  it bits per symbol would overstate the present evidence.
  \item The 256-symbol records omit raw output, environment captures, timing,
  memory, artifact hashes, and explicit repository commit fields in each
  \texttt{RUN.md}.
  \item The 1024 by 20D record used a dirty CLI file. Its diff is recorded, but
  the exact dirty tree is not represented by a commit.
  \item Peak memory was not measured. No matched brute-force/trie benchmark is
  available, and the old brute-force implementation is only recoverable from
  Git history.
  \item The recorded 1024 by 20D run is Lorenz-96, not an OmegaSim trace. Direct
  compound M1 labels are not a learned dimension-reduction or semantic state
  representation.
  \item The source and tests support category induction, persistence, and exact
  replay, but the benchmark records do not persist fitted state artifacts or
  replay them as part of the recorded workflow.
\end{itemize}

\section{Future Work}

The next experiments should preserve the exact-reconstruction invariant while
increasing scientific discriminability. First, reconstruct the historical
brute-force miner as a frozen fixture and run matched trie/brute-force cases on
identical streams, recording fit time, total process time, peak RSS, proposal
count, grammar, and score. Second, add periodic, fixed-point, stochastic, and
shuffled-surrogate controls, then pre-register grammar-derived detection
metrics. Third, vary duration, bins, dimension, initial conditions, and
symbolization bounds, with train/test separation and repeated trajectories.
Fourth, compare direct compound symbols with selective coordinates, coarser
partitions, and explicit dimension-reduction methods. Fifth, persist every
fitted grammar and replay its edit log in the experiment harness. Finally, run
the same recorded pipeline on actual OmegaSim starter traces only after their
schema, export command, and expected invariants are fixed.

Algorithmically, the current exhaustive candidate loop repeatedly applies and
scores full candidate states. The project plan identifies approximate MDL
pre-ranking, per-iteration score trajectories, joint chunk/category proposals,
and pattern-intensity logging as near-term work. These should be benchmarked
against an unchanged exact baseline so that speed improvements do not alter the
selected grammar silently.

\section{Conclusion}

The available evidence supports a narrow but useful result: the pure-Python CLA
prototype learns exact-reconstructing chunk grammars on five deterministic
control generators and remains operational on a 1024-symbol, 20-dimensional
Lorenz-96 stream using bounded suffix-trie proposal mining. High-dimensional
direct M1 streams are weakly compressed under the current approximate score,
and the latest run accepted no category edit. The records do not yet validate
CLA as a detector of strange-attractor structure or as an OmegaSim analysis
tool. Matched data-structure benchmarks, negative controls, held-out evaluation,
and actual OmegaSim traces are required for those stronger claims.
