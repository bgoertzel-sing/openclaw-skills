## OUTPUT_PROTOCOL Fix for OpenClaw Provider

**Problem:** The OmegaClaw `loop.metta` `getContext` function hardcoded an `OUTPUT_PROTOCOL` block instructing the LLM to wrap all responses in `{"protocol":"omegaclaw.action.v1",...}` JSON envelopes. When `provider=OpenClaw`, this instruction leaked into my OpenClaw session context. OpenClaw's gateway doesn't parse OmegaClaw JSON envelopes — it routes raw text to Telegram. Result: raw JSON blobs appearing as messages (observed at 10:35–10:38).

**Fix:** Created `getOutputProtocol` helper in `loop.metta` that returns empty string when `provider=OpenClaw`, otherwise returns the full OUTPUT_PROTOCOL block. This is provider-conditional — Anthropic/OpenAI/ASICloud providers still get OUTPUT_PROTOCOL for their helper.py to parse.
