OpenClaw Dedicated-Laptop Security Retrofit: Corrected Runbook

Prepared for: Ben's Pop!_OS laptop running OpenClaw / ZeroBot

Date: 2026-06-25

Purpose: Convert the current OpenClaw installation from a convenient same-user setup into a more secure split-user setup, while preserving the research-agent workspace and Telegram access.

Short version. The earlier security plan is directionally right: run OpenClaw as a dedicated low-privilege Linux user and keep browser/password-manager/Gmail/ChatGPT state under a separate human GUI user. This corrected version adapts the steps to the current install, fixes handoff-folder permissions, avoids overly broad process kills, and accounts for the fact that the OpenClaw executable currently lives under /home/ben/.npm-global.

0. Current Known State

These assumptions were verified before writing this runbook:

  • Host: Pop!_OS 22.04 LTS.
  • OpenClaw version: 2026.6.10.
  • Current OpenClaw user: ben.
  • Current OpenClaw executable: /home/ben/.npm-global/bin/openclaw.
  • Current OpenClaw config: /home/ben/.openclaw/openclaw.json.
  • Research workspace: /home/ben/research-agent.
  • Gateway: loopback-only, port 18789.
  • Telegram: enabled, polling, direct-message allowlist, groups disabled.
  • Exec policy: approval-backed allowlist with ask-on-miss.
  • Current issue: because OpenClaw runs as ben, it can potentially access files and session handles available to the normal human account, including browser profiles, SSH agent sockets, keyring/session bus paths, and Downloads.

1. Threat Model and Target Architecture

This is a practical local hardening plan, not a mathematically sealed sandbox. It is meant to reduce accidental overreach, prompt-injection damage, and casual access to human browser/password/session material.

Account or Path Role Access Rule
ben or a future human GUI user Human browser, email, ChatGPT, password manager, Downloads, normal desktop OpenClaw should not read this account's private home or GUI/session sockets.
openclaw Agent account: OpenClaw state, memory, research workspace, project logs, local experiments No sudo, no Docker group, no browser profile, no SSH agent, no GUI session.
/srv/openclaw/handoff/from-human Files intentionally given to the agent Human writes; agent reads.
/srv/openclaw/handoff/to-human Files intentionally returned by the agent Agent writes; human reads.
Important: Do not give the openclaw user sudo, membership in docker, access to /var/run/docker.sock, access to your browser profile, access to your password manager/keyring, or access to your GUI session environment.

2. Migration Style

Use a staged migration, with verification after each stage. Do not use broad destructive commands. Do not delete the original ben setup until the new openclaw setup has survived a restart and a Telegram test.

Recommended stages:

  1. Create a timestamped backup.
  2. Create the openclaw user and shared handoff group/directories.
  3. Install or expose the OpenClaw executable for the openclaw user.
  4. Copy only OpenClaw state and the research workspace into /home/openclaw.
  5. Test OpenClaw manually as openclaw.
  6. Install a system service running as openclaw.
  7. Verify Telegram, gateway binding, exec policy, memory/QMD, and file boundaries.
  8. Only later, retire the old user-level gateway service under ben.

4. Backup Before Any Change

Create a recoverable backup of the existing OpenClaw and research-agent state. This does not include all of /home/ben; it targets the relevant state.

STAMP="$(date -u +%Y%m%dT%H%M%SZ)"
BACKUP="/home/ben/openclaw-security-backups/$STAMP"
mkdir -p "$BACKUP"

rsync -aH --info=progress2 /home/ben/.openclaw/ "$BACKUP/.openclaw/"
rsync -aH --info=progress2 /home/ben/research-agent/ "$BACKUP/research-agent/"
rsync -aH --info=progress2 /home/ben/.npm-global/lib/node_modules/openclaw/ "$BACKUP/openclaw-node-module/" 2>/dev/null || true

printf 'Backup created at %s\n' "$BACKUP"

Do not store this backup in a world-readable directory. The OpenClaw state may contain tokens or local auth material.

5. Create the Dedicated Agent User

Create the openclaw Linux account with no password login. These commands require sudo.

sudo adduser --disabled-password --gecos "" openclaw
sudo chmod 700 /home/openclaw

# Make sure the account is not in privilege-bearing groups.
sudo deluser openclaw sudo 2>/dev/null || true
sudo deluser openclaw docker 2>/dev/null || true
sudo deluser openclaw adm 2>/dev/null || true
sudo deluser openclaw plugdev 2>/dev/null || true
sudo deluser openclaw lpadmin 2>/dev/null || true

id openclaw

Expected: openclaw should be in its own low-privilege group, not in sudo, docker, adm, plugdev, or lpadmin.

6. Create Corrected Handoff Directories

The original plan used chmod 730, which is awkward because the group cannot list/read the directory and new files may not inherit a useful group. Use a shared group plus setgid directories and default ACLs instead.

# Create a shared handoff group if it does not already exist.
sudo groupadd --force openclaw-handoff

# Add both the human user and agent user to the handoff group.
sudo usermod -aG openclaw-handoff ben
sudo usermod -aG openclaw-handoff openclaw

# Create the handoff tree.
sudo mkdir -p /srv/openclaw/handoff/from-human
sudo mkdir -p /srv/openclaw/handoff/to-human

# Shared ownership: root owns the dirs; group controls handoff access.
sudo chown -R root:openclaw-handoff /srv/openclaw

# 2770 = rwx for owner/group, none for others, setgid for group inheritance.
sudo chmod 2770 /srv/openclaw
sudo chmod 2770 /srv/openclaw/handoff
sudo chmod 2770 /srv/openclaw/handoff/from-human
sudo chmod 2770 /srv/openclaw/handoff/to-human

# Default ACLs make newly created files/directories group-readable/writable.
sudo setfacl -m g:openclaw-handoff:rwx /srv/openclaw/handoff/from-human /srv/openclaw/handoff/to-human
sudo setfacl -d -m g:openclaw-handoff:rwx /srv/openclaw/handoff/from-human /srv/openclaw/handoff/to-human
sudo setfacl -d -m m::rwx /srv/openclaw/handoff/from-human /srv/openclaw/handoff/to-human

ls -ld /srv/openclaw /srv/openclaw/handoff /srv/openclaw/handoff/from-human /srv/openclaw/handoff/to-human
getfacl /srv/openclaw/handoff/from-human /srv/openclaw/handoff/to-human
Group membership note: after usermod -aG, Ben may need to log out and back in before the new group appears in desktop terminals. For immediate terminal testing, use newgrp openclaw-handoff or test via sudo.

7. Make OpenClaw Executable Available to the Agent User

The current OpenClaw executable is under /home/ben/.npm-global. The openclaw user should not depend on access to /home/ben. Choose one of these approaches.

Preferred Option: Install OpenClaw for the openclaw User

If the OpenClaw npm package can be installed without needing Ben's home directory, install it while logged in as openclaw.

sudo -iu openclaw
mkdir -p ~/.npm-global
npm config set prefix "$HOME/.npm-global"
printf '\nexport PATH="$HOME/.npm-global/bin:$PATH"\n' >> ~/.profile
export PATH="$HOME/.npm-global/bin:$PATH"

# Install the same OpenClaw package/version used by this machine.
# If this exact package name/version differs, inspect the current install first.
npm install -g openclaw@2026.6.10

command -v openclaw
openclaw --version
exit

Fallback Option: Install Under /opt/openclaw

If user-local npm install is not desirable, install OpenClaw into a root-owned shared location and expose only the executable, not Ben's home directory.

sudo mkdir -p /opt/openclaw
sudo chown root:root /opt/openclaw
sudo chmod 755 /opt/openclaw

# Example only. Adapt to the exact package/install method if needed.
sudo npm install -g --prefix /opt/openclaw openclaw@2026.6.10
sudo ln -sf /opt/openclaw/bin/openclaw /usr/local/bin/openclaw

sudo -iu openclaw command -v openclaw
sudo -iu openclaw openclaw --version

Do not make /home/ben/.npm-global world-readable just to make this work.

8. Stop the Old User-Level Gateway Carefully

Do not use pkill -f openclaw as the default. Stop the known user-level service first, then inspect.

# As ben:
systemctl --user status openclaw-gateway --no-pager 2>/dev/null || true
systemctl --user stop openclaw-gateway 2>/dev/null || true

# Check what remains.
ps -eo user,pid,ppid,cmd | grep -i openclaw | grep -v grep || true
ss -ltnp | grep 18789 || true

If a foreground OpenClaw TUI/session is running, close it normally. Only kill specific leftover PIDs after reading the command line.

9. Copy State to /home/openclaw

Copy only the OpenClaw state and research workspace. Do not copy all of /home/ben, Downloads, browser profiles, SSH keys, password stores, or GUI config.

sudo mkdir -p /home/openclaw/migration-import
sudo rsync -aH --info=progress2 /home/ben/.openclaw/ /home/openclaw/migration-import/.openclaw/
sudo rsync -aH --info=progress2 /home/ben/research-agent/ /home/openclaw/migration-import/research-agent/
sudo chown -R openclaw:openclaw /home/openclaw/migration-import

sudo -iu openclaw bash -lc '
set -euo pipefail
cp -a ~/migration-import/.openclaw ~/.openclaw
cp -a ~/migration-import/research-agent ~/research-agent
chmod 700 ~/.openclaw ~/research-agent
find ~/.openclaw -type d -exec chmod 700 {} +
'

sudo -iu openclaw ls -ld /home/openclaw/.openclaw /home/openclaw/research-agent

10. Adapt OpenClaw Config for the New Home

As openclaw, inspect the copied config. The goal is to preserve the known secure posture:

  • Workspace: /home/openclaw/research-agent.
  • Gateway bind: loopback.
  • Gateway auth token source: local secrets file, not plaintext in JSON.
  • Telegram bot token source: local secrets file, not plaintext in JSON.
  • Telegram DM allowlist retained.
  • Telegram groups disabled.
  • Exec mode: ask.
  • Elevated execution disabled.
sudo -iu openclaw bash -lc '
set -euo pipefail
node - <<"NODE"
const fs = require("fs");
const p = process.env.HOME + "/.openclaw/openclaw.json";
const c = JSON.parse(fs.readFileSync(p, "utf8"));
c.workspace = process.env.HOME + "/research-agent";
c.gateway = c.gateway || {};
c.gateway.mode = "local";
c.gateway.bind = "loopback";
c.gateway.port = 18789;
c.channels = c.channels || {};
c.channels.telegram = c.channels.telegram || {};
c.channels.telegram.enabled = true;
c.channels.telegram.dmPolicy = "allowlist";
c.channels.telegram.groupPolicy = "disabled";
c.tools = c.tools || {};
c.tools.exec = c.tools.exec || {};
c.tools.exec.mode = "ask";
c.tools.elevated = c.tools.elevated || {};
c.tools.elevated.enabled = false;
fs.writeFileSync(p, JSON.stringify(c, null, 2) + "\n");
NODE
chmod 600 ~/.openclaw/openclaw.json
openclaw exec-policy show
'
Do not print secrets. If you inspect ~/.openclaw/secrets.json, check only file mode and key presence, not token values.

11. Manual Gateway Test as openclaw

Before installing a system service, start the gateway as openclaw in a test shell.

sudo -iu openclaw
export PATH="$HOME/.npm-global/bin:/usr/local/bin:/usr/bin:/bin:$PATH"
openclaw gateway --port 18789

In a second terminal, verify:

sudo -iu openclaw openclaw gateway status --deep
sudo -iu openclaw openclaw channels status --probe
ss -ltnp | grep 18789 || true
ps -eo user,pid,ppid,cmd | grep -i openclaw | grep -v grep || true

Expected:

  • Gateway is reachable.
  • Gateway listens on loopback only.
  • Telegram probe works.
  • The gateway process is owned by openclaw, not ben.

After the manual test, stop the foreground gateway with Ctrl-C.

12. Install a System Service

Create a system-level service owned by openclaw. Adjust PATH if the executable path differs.

sudo tee /etc/systemd/system/openclaw-agent.service >/dev/null <<'UNIT'
[Unit]
Description=OpenClaw Agent Gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=openclaw
Group=openclaw
WorkingDirectory=/home/openclaw
Environment=HOME=/home/openclaw
Environment=PATH=/home/openclaw/.npm-global/bin:/usr/local/bin:/usr/bin:/bin
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/home/openclaw /srv/openclaw /tmp/openclaw
ExecStart=/usr/bin/bash -lc 'exec openclaw gateway --port 18789'
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
UNIT

sudo systemctl daemon-reload
sudo systemctl enable openclaw-agent
sudo systemctl start openclaw-agent
sudo systemctl status openclaw-agent --no-pager

If the service fails, inspect logs without printing secrets:

journalctl -u openclaw-agent -n 120 --no-pager

13. Disable the Old ben User Gateway Service

Only after the openclaw-agent system service works, disable the old user-level service under ben.

systemctl --user disable --now openclaw-gateway 2>/dev/null || true
systemctl --user status openclaw-gateway --no-pager 2>/dev/null || true
systemctl status openclaw-agent --no-pager
ps -eo user,pid,ppid,cmd | grep -i openclaw | grep -v grep || true

Expected: the durable gateway should be the system service owned by openclaw.

18. Rollback Plan

If the new service fails and you need to return to the previous setup:

sudo systemctl disable --now openclaw-agent 2>/dev/null || true

# Re-enable the old user-level gateway as ben, if it still exists.
systemctl --user enable --now openclaw-gateway 2>/dev/null || true
openclaw gateway status --deep
openclaw channels status --probe

If state was corrupted, restore from the backup created in Section 4. Do not delete /home/ben/.openclaw or /home/ben/research-agent until the new setup has been stable for several days.

19. Operating Rules After Migration

  • OpenClaw runs as openclaw, not as ben.
  • Files for the agent go in /srv/openclaw/handoff/from-human.
  • Files from the agent go in /srv/openclaw/handoff/to-human.
  • The agent should not browse human home directories, browser profiles, password stores, keyrings, SSH agents, GUI sessions, Docker sockets, or other users' private files.
  • Use explicit approval for package installs, GitHub writes, cloud/paid compute, Docker/Podman, credential setup, chmod/chown, systemctl, SSH key changes, and broad deletions.
  • Keep Telegram in direct-message allowlist mode unless there is a specific reason to change it.
  • Keep the gateway loopback-only unless you deliberately add a tailnet/reverse-proxy design.
