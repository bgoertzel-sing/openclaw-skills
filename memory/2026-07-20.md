## 00:30 PDT — ePC r6 crash root cause found and fixed

- **Root cause:** `del student_template` inside the arm loop in
  `scripts/run_gpt2_mechanism_screen.py`. The variable `student_template`
  was created once before the loop and deleted on each iteration. After the
  first arm (bp_ce) deleted it, the second iteration (bp_kd) raised
  `NameError` — but only after bp_kd's JSON was saved. This explains why
  exactly 2 arms completed and no ePC arm ran.
- **Why no traceback was captured:** the launch wrapper used
  `python3 ... 2>&1 | tee logfile; echo EXIT_CODE=$?` without `pipefail`.
  `$?` captured tee's exit code, not Python's. The traceback was likely
  in the pipe buffer but not flushed to the file.
- **Fix (commit `e50ed24` on `agent/epc-outcome-probes`):**
  1. Removed `del student_template` from the loop body; moved cleanup to
     after `init_state` capture (`del student_init, student_template`).
  2. Removed unused `GPT2BlockStateAdapter(student)` construction in
     `run_arm` ePC branches (`gpt2_epc_objective` creates its own adapter).
  3. Added try/except around the arm loop to capture and log tracebacks.
- **Verified:** ePC objective runs fine on CPU (6-layer GPT-2, d=768,
  batch=4, seq=256) and on A100 GPU with bf16 autocast. No OOM, no
  numerical issues. VRAM usage < 1GB for a single ePC step.
- **Next:** need fresh approval to rerun the mechanism screen on RunPod.
  The $10 from the r6 run is consumed (~$5.62 actual spend).
